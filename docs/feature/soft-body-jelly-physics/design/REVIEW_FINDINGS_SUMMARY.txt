================================================================================
MAJOR ISSUES (IMPLEMENTATION DETAILS)
================================================================================

M-01: Animation Renderer Integration Missing Key Details
  Location: architecture-design.md §3 (IP-3), component-boundaries.md
  Issue: Unclear how AnimationRenderer tracks soft body IDs, filters shapes,
         and manages DeformableMesh pointers for per-frame updates.
  Action: Add per-frame update loop diagram showing shape filtering and
          soft body storage strategy.

M-02: Data Model Inconsistency in SoftBodyMeshData
  Location: data-models.md §2
  Issue: Unclear if face_indices are returned every frame (wasteful) or
         cached at creation time (efficient).
  Action: Choose caching strategy and document it. Recommend caching.

M-03: BodyType Enum Extension Does Not Cover All Switch Statements
  Location: data-models.md line 99, architecture-design.md §8
  Issue: Design mentions one SOFT case (map_body_type_to_motion) but lacks
         complete audit of all BodyType switch statements in codebase.
  Action: Provide checklist of all switches:
    - animation_renderer.cpp::is_movable_body() must return FALSE for SOFT
    - jolt_physics_simulator.cpp::map_body_type_to_motion() must handle SOFT
    - yaml_scene_loader.cpp::parse_body_type() must map "soft" string
    - validator.cpp and other locations must be checked

M-04: Normal Recomputation Algorithm Under-Specified
  Location: data-models.md §3
  Issue: Algorithm description correct but lacks pseudocode and edge case
         handling (degenerate faces, single-face vertices).
  Action: Add detailed pseudocode under update_vertices() Contract,
          including edge case handling.

m-01: Font Mesh Generator Output Type Inconsistency
  Location: data-models.md §7
  Issue: FontMeshResult uses separate vertex/normal indices (TriangleMesh style)
         but DeformableMesh uses flat layout. Scope unclear.
  Action: Clarify FontMeshResult is for TriangleMesh rendering only.

m-02: GPU SceneFlattener Handling Mentioned But Not Specified
  Location: architecture-design.md KD-6
  Issue: CPU-only rendering stated but unclear if SceneFlattener already skips
         unknown shapes or if new code needed.
  Action: Verify and document implementation behavior.
